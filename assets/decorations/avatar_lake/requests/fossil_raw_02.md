# 기계 암모나이트 화석 raw 02 생성 요청서

- 대상: ChatGPT 이미지 생성
- 계약: 데코레이션 레이어 최소 설계안(2026-09-15 승인). 지형 경계 계약은 [`docs/decisions/0011-terrain-boundary-assets.md`](../../../../docs/decisions/0011-terrain-boundary-assets.md)
- 받을 파일: `assets/decorations/avatar_lake/source/fossil_raw_02.png`
- 상태: **주력 역할은 불채택, 보조 대형 기계 화석·거친 화석 유물로 승인(2026-09-16).** 승인 에셋 `runtime/fossil02_relic.png`(64×48, sha256 `1ee77c35…`), `behind` 로 (3100, 541)과 (9120, -809, 좌우 반전). 주력 raw01 과 다른 형태의 희귀 발견물이다. 원본 `source/fossil_raw_02.png` sha256 `509b7a84…bb05`. 결정은 ADR 0012
- 이 화석은 **충돌이 없는 장식**이다. 지형 타일이 아니며 플레이어가 밟거나 막히지 않는다

## 왜 다시 그리는가

raw 01 로 만든 64x48 후보는 크기와 합성 방식(`behind`, 매몰 깊이 21px)은 맞았으나 **외곽이 온전한 반원**이라 잔디에 꽂아 둔 톱니 장식처럼 보였다. 실패 화면은 `build/orch/fossil_norm/zoom_v2_1.png`, `zoom_v2_2.png` 다.

raw 01 은 폐기하지 않는다. **지면 경계용으로만 불채택**이고, 온전한 외곽이 오히려 맞는 **암반 몸통 속 완전 매몰** 배치용으로 보존한다. raw 02 는 지면 경계용 주력이고, 두 종류를 섞어 쓴다.

## 규격

| 항목 | 값 |
| --- | --- |
| 런타임 결과 | 64x48 RGBA. 가로가 긴 4:3 |
| 생성 원본 | 가로가 긴 이미지 한 장. 1280x960 이상 권장(4:3). 화석 하나만 |
| 축소 배율 | 가로세로 같은 배율 |
| 픽셀 밀도 | 이미지 가로를 약 64칸으로 나눈 격자에서 한 칸이 게임 픽셀 하나. 승인 암반 E0 와 같은 굵기감 |
| 알파 | 0 또는 255. 정규화가 만든다 |
| 팔레트 | 투명 제외 12색 이하 |
| 좌우 반전 | 허용. 좌우 방향 조명을 넣지 않는다 |
| crop | 새 구도에 맞춰 다시 정한다. 가로세로 비만 정확히 4:3 |

## 게임에서 어떻게 잘리는가 (가장 중요한 제약)

레이어는 `behind` 이고 기준점은 지형 표면보다 **21px 아래**다. 64x48 이미지를 48행으로 볼 때

| 행 | 게임에서 |
| --- | --- |
| 0 ~ 26 | **화면에 보인다.** 여기서 화석이 읽혀야 한다 |
| 27 | 지형 표면선. 이끼가 걸치는 높이 |
| 28 ~ 47 | **지형이 앞에서 덮어 보이지 않는다** |

그러므로 28행 아래에 중요한 형태를 두지 마라. 다만 비워 두지도 마라. 잘린 단면처럼 보이지 않도록 암반과 균열로 계속 이어 그린다.

## 구도

- **비대칭이 핵심이다.** 한쪽(예: 오른쪽)에서는 기계 암모나이트의 나선과 금속 마디가 **갑작스럽게 또렷하게** 드러난다. 나선 중심과 톱니 마디가 그쪽에 보인다.
- 반대쪽(왼쪽)으로 갈수록 외곽이 **깨지고** 암반 조각, 균열, 흙 속으로 불규칙하게 잠식되어 사라진다. 어디까지가 화석이고 어디부터 바위인지 경계가 분명하지 않다.
- **완전한 원형이나 반원형 외곽을 그리지 마라.** 껍데기 테두리가 한 바퀴 이어지면 실패다.
- **받침돌과 평평한 접지면을 그리지 마라.** 화석이 무언가 위에 얹혀 있으면 실패다.
- **암반이 화석 앞을 부분적으로 가린다.** 껍데기 위로 바위 덩어리나 흙 결이 겹쳐 지나가서 오래 묻혀 있었던 느낌을 준다. 앞을 가리는 면적은 드러난 부분의 1/4 안팎이다.
- 위쪽 윤곽도 매끈하지 않다. 바위에 물려 들어간 자리가 한두 군데 있다.

## 이끼

- 27행 표면선 언저리에만 **드물게** 걸친다. 몇 점으로 충분하다.
- 화석 전체를 덮거나 초원 장식처럼 보이면 실패다.
- 승인된 top 이끼와 같은 색만 쓴다. 아래 두 색은 팔레트에 반드시 남긴다.

| 용도 | RGB |
| --- | --- |
| 이끼 짙은 색 | `(51, 80, 40)` |
| 이끼 중간 색 | `(89, 127, 36)` |

밝은 연두 `(177, 188, 61)` 는 쓰지 마라. 화석 위에서 빛나 보인다.

## 색과 재질

- **암반:** 승인 E0 암반색 그대로다. 새 암반 색을 만들지 않는다.

  `(76,73,113) (83,78,116) (92,83,119) (102,89,121) (112,93,122) (130,103,124) (144,110,125) (155,117,120) (164,122,114) (173,152,136) (176,128,108) (193,133,98) (210,140,91) (241,162,91)`

- **금속:** 무광 황동. raw 01 정규화에서 나온 아래 계열을 유지한다.

  `(33,32,31) (55,51,43) (101,86,69) (128,101,62)`

- **부식:** 청록 녹은 넣더라도 아주 조금이다. 정규화에서 팔레트 12색에 밀려 탈락할 수 있으니 여기에 의존하지 마라.
- **발광:** 없다. 빛나는 코어, 네온, 발광 문양을 넣지 않는다.
- **조명:** 위에서 오는 빛만 쓴다. 좌우 방향 그림자를 넣지 않는다.

## 배경과 알파 처리

- 배경은 전체를 선명한 마젠타 단색(`#FF00FF` 에 가까운 색)으로 채운다. 그라데이션, 그림자, 바닥, 무늬를 넣지 않는다.
- 화석·암반과 배경 사이에 섞인 중간색, 번짐, 후광이 생기지 않게 경계를 또렷하게 한다.
- 정확한 배경색과 이진 알파는 raw 의 책임이 아니다. 정규화가 처리한다.

## 정규화 계약

1. 원본을 `source/` 에 받은 그대로 두고 편집·리사이즈하지 않는다.
2. 새 구도에 맞는 고정 crop 하나를 정해 기록한다. 가로세로 비는 정확히 4:3 이다.
3. 원본 해상도에서 배경을 분리하고, 마젠타 쪽으로 기운 가장자리 픽셀을 제거한다.
4. **보간 없이** 64x48 로 줄인다. 새 색을 만들지 않는다.
5. 팔레트는 투명 제외 12색 이하. 암반 계열은 E0 팔레트로 스냅하고, **이끼 두 색은 강제로 보존**한다.
6. 알파는 0 또는 255 로 출력한다. 팔레트에 배경색이나 마젠타 쪽 색이 남으면 실패다.
7. 결과는 시험 데코레이션으로만 쓰고, 플레이 판정 뒤에 승격한다.

## 금지

- 온전한 원형·반원형 외곽
- 받침돌, 평평한 접지면, 독립된 장식물·배지·꽂아 둔 톱니바퀴
- 발광, 네온, 마법 효과
- 눈, 얼굴, 캐릭터처럼 보이는 형태
- 글자, 숫자, 기호, 서명
- 원근법, 비스듬한 시점, 입체 렌더링 느낌
- 부드러운 그라데이션, 안티에일리어싱, 흐림, 사진 질감
- 화석 주변의 흙더미, 풀, 덩굴(이끼는 위 규정만큼만)
- E0 에 없는 새 암반 색
