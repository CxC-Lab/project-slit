# 0007: 지역을 코드가 아니라 데이터 파일로 둔다

- 상태: 채택
- 날짜: 2026-09-11

## 결정 내용

지역의 경계와 스폰 위치, 충돌 사각형 목록을 JSON 파일에 두고 실행 시점에 읽는다. 지형을 고치려고 다시 빌드하지 않는다.

형식은 우리가 손으로 고칠 수 있는 최소한으로 둔다. 외부 편집기 형식을 쓰지 않고, 새 의존성도 추가하지 않는다. 매니페스트에서 이미 쓰고 있는 JSON 라이브러리를 그대로 쓴다.

`PracticeRoom` 도 같은 경로로 읽는다. 지역을 읽는 방법은 하나뿐이다.

## 배경

지금까지 지형은 `PracticeRoom.cpp` 안의 사각형 목록이었다. 지역이 하나뿐이고 이동 규칙을 검증하는 용도일 때는 문제가 아니었다.

그런데 다음 단계가 "넓은 공간을 떠다니는 감각"을 만드는 일이다. 이런 공간은 계산해서 나오지 않고 고쳐 보면서 찾아야 한다. 발판 하나를 옮길 때마다 다시 빌드해야 하면 그 반복을 할 수 없다. 실제로 막는 것은 이것 하나였다.

## 검토한 대안

- 지금처럼 코드에 둔다: 추가 구조가 없다. 다만 고쳐 보는 반복이 불가능하다.
- Tiled 같은 편집기 형식을 읽는다: 시각적으로 편집할 수 있고 레이어와 오브젝트를 다룰 수 있다. 다만 형식을 읽는 코드나 의존성이 필요하고, 타일 단위와 레이어 구조를 함께 정해야 한다. 아직 타일을 쓸지도 정하지 않았다.
- 우리 형식의 JSON 을 손으로 고친다: 의존성이 늘지 않고 형식을 우리가 정한다. 다만 시각적 편집이 아니라 숫자를 직접 다뤄야 한다.

## 선택 이유

세 번째를 택했다. 막고 있던 것은 "다시 빌드해야 한다"였지 "시각적으로 편집할 수 없다"가 아니었다. 숫자를 고치고 다시 실행하는 것만으로 그 반복이 가능해진다.

Tiled 는 손으로 JSON 을 고치는 일이 실제로 힘들어졌을 때 다시 본다. 지금 도입하면 타일 크기와 레이어 구조를 쓰지도 않을 상태에서 먼저 정해야 한다. 이는 필요해질 때까지 계층을 만들지 않는다는 [`0002-minimal-source-structure.md`](0002-minimal-source-structure.md) 의 기준과 어긋난다.

같은 이유로 폴리곤 충돌도 넣지 않았다. 경사면을 영구히 제외했으므로 사각형으로 충분하고, 영영 필요하지 않을 수도 있다.

지역을 읽는 방법을 하나로 둔 이유는 단순하다. 둘로 갈리면 앞으로 지역이 늘어날 때마다 두 벌을 관리하게 된다. `PracticeRoom` 을 옮길 때 경계와 스폰, 지형 열여섯 개의 값을 한 자리도 바꾸지 않았고 기존 검사로 확인했다.

## 제약

지역의 가로 시작점은 0 이어야 한다. 플레이어에게 넘기는 가로 한계가 지역 폭이라, 시작점이 0 이 아니면 경계 계산이 어긋난다. 이 제약은 문서에만 적어 두지 않고 읽는 시점에 검사해 어긋나면 실패시킨다. 나중에 시작점이 0 이 아닌 지역이 필요해지면 플레이어 쪽 계약부터 고쳐야 한다.

크기는 화면 단위로 판단한다. 16:9 화면에서 한 화면에 보이는 범위가 800x450 이므로 그것을 한 화면으로 센다. 첫 그레이박스 지역은 가로 열두 화면, 세로 열두 화면이다.

## 되돌릴 조건

- 손으로 JSON 을 고치는 일이 실제로 힘들어진 경우. 지형 개수가 많아지거나 배치를 눈으로 보며 조정해야 할 때다. 이때 Tiled 같은 편집기 형식을 다시 본다.
- 타일 기반으로 가기로 정한 경우. 형식 자체가 달라진다.
- 지역마다 배경 레이어나 오브젝트, 카메라 구역처럼 사각형 목록으로는 표현할 수 없는 것이 필요해진 경우.

되돌릴 때도 지역을 읽는 방법은 하나로 유지한다.
