# 0009: 지형 타일을 충돌 데이터에서 유도한다

- 상태: 채택
- 날짜: 2026-09-12

## 결정 내용

지형의 시각 표현을 위한 별도 타일맵 데이터를 만들지 않는다. 이미 있는 충돌 사각형 목록에서 타일 배치를 유도한다. 지형을 만드는 경로는 여전히 `solids` 하나뿐이다.

통짜 지형 텍스처를 쓰지 않는다. 기본 지형은 월드 전용 타일로 통일하고, 컨셉아트에 가까운 고유 표현은 충돌 없는 데코레이션으로 따로 얹는다.

### 타일 크기는 데이터에서 읽는다

타일셋 메타데이터 파일이 크기와 역할별 변형 개수를 가진다.

```json
{ "image": "avatar_lake.png", "tileSize": 20,
  "roles": { "inner": 4, "top": 3, "slab": 2, "left": 2, "right": 2, "bottom": 2,
             "top_left": 1, "top_right": 1, "bottom_left": 1, "bottom_right": 1 } }
```

지역 파일은 타일셋 이름만 가진다. 그 필드가 없으면 단색으로 그린다. 실패가 아니다.

Avatar Lake 는 20 을 쓴다. 다른 월드가 16 이나 32 를 고를 수 있어야 하므로 코드에 크기를 두지 않는다.

### 연결된 덩어리는 하나의 격자를 공유한다

겹치거나 변이 맞닿는 사각형을 연결 요소로 묶고, 한 덩어리 안에서는 공통 원점으로 타일을 깐다. 사각형마다 격자를 다시 시작하면 맞닿은 자리에서 무늬가 어긋난다.

역할 판정은 개별 사각형이 아니라 전체 합집합을 기준으로 한다. 그래서 맞닿은 면에는 모서리가 아니라 내부가 온다.

### 열 개의 역할은 형태이지 아트가 아니다

`inner`, `top`, `bottom`, `left`, `right`, 네 모서리, 그리고 위아래가 모두 빈 한 칸 높이 발판을 위한 `slab` 이다. 47 종 오토타일을 목표로 하지 않는다.

한 역할에 변형이 여러 개일 수 있다. 변형은 타일의 월드 좌표와 지역 seed 의 결정적 해시로 고른다. 실행할 때마다 바뀌면 미리보기와 게임이 어긋난다. 구현마다 다른 `std::hash` 를 쓰지 않고 고정된 알고리즘을 직접 쓴다.

### 늘리지 않고 자른다

충돌 좌표는 어떤 타일 크기에도 맞지 않으므로 외곽에 자투리가 생긴다. 자투리는 텍스처를 잘라 처리한다. 한 조각이라도 늘어나면 픽셀 아트가 뭉개진다.

모서리 역할의 아트는 실제 충돌 경계에 붙는다. `top` 이면 타일의 맨 윗줄이 지형 표면에 오고 안쪽에서 잘린다. 표면 쪽을 자르면 풀이나 모서리 장식이 사라진다. 내부는 반대로 격자 위상대로 매핑해 무늬가 덩어리 안에서 이어지게 한다.

## 배경

배경 레이어와 이동이 자리를 잡은 뒤 남은 것이 지형의 시각 표현이었다. 지형은 계속 회색 사각형이었다.

통짜 텍스처를 쓰면 사각형마다 그림을 맞춰야 하고, 사각형 하나를 옮길 때마다 그림을 다시 그려야 한다. 지형을 데이터로 둔 이유가 고쳐 보는 반복을 가능하게 하려는 것이었는데 그 이점이 사라진다.

## 검토한 대안

- 통짜 지형 텍스처: 자유도가 높다. 다만 지형을 고칠 때마다 그림을 다시 그려야 하고 타일 단위 재사용이 없다.
- 별도 타일맵 데이터: 시각과 충돌을 따로 둘 수 있다. 다만 두 벌을 관리해야 하고 어긋날 수 있다. 편집 도구도 필요해진다.
- 47 종 오토타일: 모서리 표현이 풍부하다. 다만 지금 필요한 것에 비해 아트 물량과 규칙이 크다.

## 선택 이유

충돌 사각형에서 유도하는 방식을 택했다. 관리할 데이터가 늘지 않고 시각과 충돌이 어긋날 수 없다. 말과 그림으로 지형을 지시하고 좌표로 옮기는 현재 작업 방식이 그대로 유지된다는 점이 결정적이었다. `solids` 를 고치면 타일이 따라온다.

역할을 열 개로 줄인 것은 지금 필요한 것이 그만큼이기 때문이다. 오목한 안쪽 모서리는 아직 쓰지 않는다. 필요해지면 역할을 늘리면 되고 데이터 구조는 그대로다.

## 되돌릴 조건

- 지형이 사각형으로 표현되지 않게 된 경우. 경사면이나 폴리곤을 쓰기로 하면 역할 판정부터 다시 본다.
- 오목한 안쪽 모서리나 더 풍부한 전이가 실제로 필요해진 경우. 역할을 늘리는 것으로 시작하고, 그래도 부족하면 오토타일을 다시 본다.
- 한 덩어리 안에서 서로 다른 재질이 필요해진 경우. 지금은 지역마다 타일셋이 하나다.

## 열린 질문

- 맞닿은 두 덩어리 사이는 위상이 다르므로 무늬가 이어지지 않는다. 내부 타일을 저대비로 그리면 거의 보이지 않지만, 뚜렷한 무늬를 쓰면 드러난다. 실제 아트에서 판단한다.
- 실제 레벨을 설계할 때 처음부터 타일 격자 위에서 그릴 것인가. 그러면 자투리가 사라진다. 현재 지형은 연습용 초안이라 맞추지 않았다.
- 데코레이션의 아틀라스 구성과 배치 규칙. 다음 작업에서 정한다.
