# 0012: Avatar Lake 데코레이션 레이어

- 상태: 채택
- 날짜: 2026-09-16

## 결정 내용

지형 타일과 별도로 **충돌 없는 시각 장식 레이어**를 둔다. 첫 적용 대상은 Avatar Lake 이며, 사용자가 플레이로 승인한 화석 3종과 암석 장식 3종을 기본 화면에 연결한다.

### 데이터

- 리전 JSON 의 `"decorations": "<name>"` 이 `assets/decorations/<name>.json` 을 가리킨다. `tileset` 과 같은 방식이다.
- 파일은 `items` 배열이다. 항목마다 `image`(파일 기준 상대 경로), `position`(이미지 **아래 가장자리 중앙**의 월드 좌표), `layer`(`behind` | `above`), `flipX` 를 둔다. 1 텍셀은 1 월드 단위다.
- 기본 데이터는 승인 에셋(`<region>/runtime/`)만 참조한다. `runtime/trials/`, `build/`, 시험 JSON 을 참조하지 않는다. 자동 검사가 이를 확인한다.
- 실행 옵션: 리전 기본값을 쓴다. `--decorations <file>` 은 시험 세트로 바꾸고, `--decorations none` 은 끈다. `--tileset` 으로 타일셋을 바꾸면서 `--decorations` 를 주지 않으면 장식을 싣지 않는다. 이렇게 해야 debug·시험 타일셋 화면이 지형만의 기준 캡처와 비교 가능하게 남는다.
- 캡처 메타데이터에 장식 파일, fnv1a64 해시, 모드(`region_default` | `override` | `disabled`)를 기록한다.

### 원칙

- **장식은 충돌이 없다.** `solids` 를 바꾸지 않고, 이동·충돌·카메라 계산에 쓰이지 않는다.
- **렌더 순서:** 배경 → `behind` 장식 → 지형 → `above` 장식 → 플레이어.
  - `behind`: 지형이 장식 위에 그려진다. 지형 표면 아래로 내려간 부분은 실제로 가려지고 top 이끼가 앞을 지난다.
  - `above`: 지형 위, 플레이어 뒤에 그려진다. 지형 앞을 지나야 하는 조각에만 쓴다.
- **결정적 순서:** 같은 레이어 안에서는 파일에 적힌 순서대로 그린다. 같은 텍스처가 연속될 때만 한 번에 제출하므로 A·B·A 순서의 가림이 유지된다.
- **카메라 밖 제외:** 뷰 사각형과 겹치지 않는 항목은 정점을 만들지 않는다.
- **지형 오해 방지:** 표면 위로 솟는 장식 윤곽은 몇 픽셀 안에서 불규칙하게 끝나야 하고, 평평한 윗면이나 받침돌처럼 보이면 안 된다. raw03 전경의 E0 덩어리는 표면 위 최대 7px, 공중에 뜬 픽셀 0 으로 만들었다.
- 지형 경계 에셋(ADR 0011)에는 식물을 넣지 않고, 식물·덩굴·솟는 암석은 이 레이어에서 다룬다.

### 매달린 덩굴 3종 (2026-09-16 승인)

암벽 아랫면과 돌출부에서 아래로 매달려, 긴 수직 암벽의 반복을 가로로 끊는다. 승인 화면은 `build/orch/vine/cap/vine2/preview_1.png`, `preview_2.png` 이고 시험 세트 해시는 fnv1a64 `16c7e63eeca4f042`, 연결 뒤 기본 데이터 해시는 `33926fdeed349206` 이다.

| 종류 | 캔버스 | 형태 | 좌우 반전 |
| --- | --- | --- | --- |
| `vine_short` | 20×36 | 잎이 적고 짧게 갈라진다 | 허용 |
| `vine_mid` | 24×56 | 두세 갈래, 갈래 길이가 다르다 | 허용 |
| `vine_long` | 32×80 | 중심 줄기와 가는 보조 줄기 | 허용하되 한 화면에 원본과 반전본을 같이 쓰지 않는다 |

**부착 좌표 계산.** 기준점은 다른 장식과 같은 이미지 아래 가장자리 중앙이므로 매달린 장식은 부착면에서 거꾸로 센다.

    position.y = 부착면 y + 캔버스 높이 - 2

끝의 -2 는 위 2행을 지형 아랫면과 겹치기 위한 값이다. 이 겹침이 없으면 각 덩굴의 맨 윗행이 1~5px 로 가늘어 뿌리가 떠 보인다. 겹친 초록은 자리마다 5~16px 이고 전부 경계 2행에 있어 top 이끼 띠와 이어진다.

**배치 제약.**

- 덩굴 끝 아래로 통과 공간 64px 이상을 남긴다(플레이어 48px + 여유). 현재 네 자리는 66, 86, 382, 236px 다.
- 발판 끝과 착지 지점에서 24px 이상 떨어뜨린다.
- 잡거나 오를 수 있는 물체로 보이지 않게, 폭이 3px 이하로 얇게 이어지는 구간을 짧게 유지한다. 승인 에셋은 2~4px 다.
- 색은 승인 top 이끼 팔레트 8색이고 밝은 연두 두 색의 합은 불투명 픽셀의 5% 이하다(현재 1.6~4.1%).

### 벽면 식생 W1·W2 (2026-09-19 승인)

암벽의 **순수 inner 앞면**에 붙어 퍼지는 잎 군집이다. 넓은 암벽과 긴 기둥에서 120px 반복 무늬를 불규칙하게 끊는다. 원본은 `source/wall_vine_raw_02.png`, 주문서와 판정 기록은 `requests/wall_vine_raw_02.md` 이다.

| 종류 | 캔버스 | 역할 | 배치 수 |
| --- | --- | --- | --- |
| `wall_vine_w2` | 56×44 | 넓은 포복형. 암벽 앞면을 가로·대각으로 끊는 **주력** | 24 |
| `wall_vine_w1` | 24×36 | 작은 균열 군집. W2 사이의 작은 균열과 빈 공간을 채우는 **보조** | 28 |

- **캔버스:** 원본 구역을 보간 없이 정확히 1/10 로 줄였다. 원본이 주문한 최대 크기보다 커서 주문 캔버스(28×28, 44×40) 대신 실제 1/10 결과(23×35, 53×43)가 들어가는 가장 작은 캔버스를 썼다. 확대나 잘라내기는 하지 않았다.
- **개수와 면적:** 같은 종류를 연속으로 두지 않기 때문에 개수는 W1 이 많다. 식생 면적은 W2 가 약 70% 다.
- **내부 틈 검사 예외:** 자동 검사 "내부 틈 + 분리 조각 3 이상"은 W1·W2 모두 불통과(1)이며 provenance 의 `checks` 에 그대로 남긴다. 사용자 육안 판정이 다음 근거로 예외 승인했다: 식생 bbox 안 암벽 노출 W1 54.2%·W2 56.3%, 외곽 오목 W1 6곳·W2 14곳, 실제 화면에서 속이 찬 판으로 보이지 않음.

**구간별 밀도 정책.** 화면 속 암반 픽셀 대비 식생 픽셀 비율이다. 크기를 키우는 대신 밀도로 조절한다(같은 화면 1.5 / 2.4 / 3.1% 비교에서 작게 느껴지는 원인이 밀도로 판정됐다).

| 구간 | 목표 | 승인 배치의 실측 |
| --- | --- | --- |
| 조용 | 약 1~1.5% | 긴 지면 800px 구간마다 0.6~1.6%(평균 약 1.1%), 기둥2 위쪽 0.4~1.5% |
| 일반 (기본) | 약 2~2.5% | 왼쪽 아래 지면 2.3%, 중앙 구조물 2.0%, 기둥 아래·중간 1.9~2.1% |
| 녹음 강조 | 약 3~3.5% | 넓은 왼쪽 계단 암벽 3.0%. 모든 화면을 고밀도로 채우지 않는다 |

**배치 원칙.**

- 모두 `above`. inner·top 시작 배치는 불투명 픽셀의 98% 이상, 가장자리 안쪽 배치는 70% 이상이 순수 inner(side 12, top 16, bottom 8 밴드 제외) 위에 있다.
- top 이끼 바로 아래 음영에서 시작하는 배치는 `position.y = 윗면 y + 16 - 2 + 캔버스 높이` 다. 가장자리 안쪽 배치는 불투명 끝을 면에서 6~8px 안쪽에 둔다.
- **암벽 결을 따른다.** 계획 위치 주변 ±16px(조건에 막히면 ±40px)에서 식생의 어두운 35% 픽셀이 보라색·어두운 균열 위에 오고, 패치 중심이 밝은 주황 하이라이트를 피하는 곳을 골랐다. 식생과 균열의 어두운 부분이 겹쳐 스티커처럼 떠 보이지 않게 한다.
- 같은 구조물 안의 위·아래 간격과 같은 줄의 가로 간격은 120px 배수(±4)를 피한다. 가까운 두 패치는 x·y 가 동시에 텍스처 위상 ±6 안에 들지 않게 한다.
- 원본과 반전을 절반씩 섞고(26/26), 이웃한 패치는 종류나 반전·높이가 다르게 한다.
- 착지면 위 공중과 기둥 아래 80px 의 벽타기 진입부는 비운다. 기존 장식 사각형과 4px 안에서 겹치지 않는다. 기둥3 윗면은 `fossil02_relic` 이 있어 top 시작 배치를 하지 않았다.

**W3 불채택.** 같은 원본의 세 번째 구역(W3 긴 파편형, 40×88 시험)은 세로로 이어진 하나의 몸통, 사람·해마·척추 같은 형상으로 읽혔다. 원본과 반전의 반복이 쉽게 드러났고, 매달린 덩굴과 역할이 겹쳤다. 기록만 `runtime/trials/` 에 `status: rejected` 로 남기고 어떤 데이터도 참조하지 않는다. 대체형은 top 수풀과 모서리 식생을 적용한 뒤 필요할 때만 만든다.

**승인 캡처와 해시.** 최종 후보 시험 세트 fnv1a64 `2f498556395e2272`, 승인 캡처는 `build/orch/wallvine2/final/cap/final/preview_1~25.png` 와 대표 화면 `rep_*.png` 다. 연결 뒤 기본 데이터는 67항목, fnv1a64 `38fb6db76db51d6a` 이다. 같은 25개 카메라에서 정식 데이터가 시험 세트와 픽셀 동일하고, 이전 기본 화면과 비교해 W1·W2 사각형 밖과 기존 15개 장식 사각형 안의 변경이 0px 이다.

## 배경

지형 경계 에셋이 끝난 뒤, 암반만으로는 발견할 거리가 없어 장식을 시험했다. 화석은 여러 번 불채택된 끝에 결정됐다. 기록은 `assets/decorations/avatar_lake/requests/fossil_raw_0N.md` 에 있다.

## 선택 이유

- **raw01 을 주력으로 한 이유:** 사용자 플레이 비교에서 가장 자연스러웠다. 결정적 차이는 그림이 아니라 레이어였다. 같은 raw01 이 `above` 에서는 실패했고 `behind` 에서는 실제 top 이끼가 가려 지형에 박힌 모습이 됐다.
- **raw03 만 전경을 쓰는 이유:** 파편층은 낮고 옆으로 퍼져 표면선과 거의 같은 높이에서 끝난다. `behind` 만으로는 파편 아랫선이 이끼선 위에 얹혀 보여, E0·top 을 렌더러와 같은 위상으로 샘플한 전경으로 아랫선을 8~9 곳 끊었다.
  - 샘플 좌표는 `월드 − 연결 성분 원점` 이다. 따라서 **전경은 배치 위치에 종속**되고 위치마다 한 장씩 따로 만든다.
  - 지형이나 타일셋이 바뀌면 전경을 다시 파생해야 한다. 파생 때 기본 지형 캡처와 inner·top 이 100% 일치하는지 확인했다.
- **raw04 를 연결하지 않는 이유:** 복잡한 암반 블렌딩은 가장 많은 조건을 수치로 맞췄지만 화면에서 덧댄 패치로 읽혔다. 이 레이어는 단순한 `behind`/`above` 조합이 더 자연스럽다는 결론을 따른다.

| `avatar_lake/requests/` | 생성 주문서와 사용자 스케치. 각 문서 상단에 역할·판정 상태 |
| `avatar_lake/runtime/*.png` | 승인 에셋. 옆의 `.provenance.json` 에 `status: approved`, sha256, 역할, 배치, 원본 해시, 정규화·파생 규칙, 승인 캡처 |
| `avatar_lake/runtime/trials/` | 불채택 시험 기록. raw04 는 `status: trial`(시험 세트가 참조), 벽 덩굴 raw01 과 벽면 식생 W3 는 `status: rejected`(어떤 데이터도 참조하지 않음). 기본 데이터는 참조하지 않는다 |

정규화·파생 스크립트는 `build/` 의 실험 도구라 커밋하지 않는다. 규칙과 입력 해시는 provenance 에 남긴다.

## 확장 범위

foliage, 덩굴, 큰 암석 장식도 같은 `items` 구조로 추가한다. 매달린 덩굴이 첫 사례다. 다음은 수직 암벽 면에 밀착해 자라는 부착형 벽 덩굴이며, 아래로 곧게 늘어진 형태는 매달린 덩굴과 역할이 겹치므로 쓰지 않는다. 새 장식은 시험 JSON 과 `runtime/trials/` 에서 플레이 판정을 받은 뒤 `runtime/` 으로 승격한다.

## 되돌릴 조건

- 장식이 밟을 수 있는 지형으로 오해된다는 플레이 보고가 나오면 해당 항목의 레이어나 윤곽을 다시 판정한다.
- 지형 형태나 타일셋 위상이 바뀌면 raw03 전경을 다시 파생하거나 해당 배치를 뺀다.
- 장식 수가 늘어 제출 비용이 문제가 되면 텍스처 아틀라스로 바꾼다. 데이터 계약은 유지한다.
