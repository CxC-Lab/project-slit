# 배경 에셋 계약

이 문서는 시차 배경 레이어 이미지를 만들 때 지켜야 하는 규격을 정리한다. 결정의 배경과 되돌릴 조건은 [`decisions/0008-parallax-background-layers.md`](decisions/0008-parallax-background-layers.md)에 있다.

여기 있는 수치 중 시차 계수와 레이어 구성은 아직 확정이 아니다. Avatar Lake 검증용 임시 이미지에서 나온 후보값이며, 실제 아트로 교체한 뒤 다시 판단한다. 반면 알파 규칙과 리샘플 금지, 세로 커버리지 부등식은 규격이며 임의로 바꾸지 않는다.

## 좌표와 단위

모든 수치는 월드 단위다. 픽셀이 아니라 월드 단위로 생각한다. 배경 텍셀 하나가 월드 단위 하나이므로 두 값은 배율 1로 같다.

레이어의 왼쪽 위 모서리 위치는 카메라 중심에서 나온다.

```
position = anchor + cameraCenter * (1 - parallax)
```

`parallax` 가 1 이면 월드에 붙어 함께 움직이고, 0 이면 화면에 붙어 따라온다. 작을수록 멀리 있는 것처럼 보인다.

보이는 세로 범위는 화면비에 따라 다르다. 전체 화면 16:9 는 800x450, 창 모드 4:3 은 800x600 이다. 세로로 더 넓게 보이는 4:3 이 대부분의 제약을 결정한다.

## 현재 Avatar Lake 레이어

Greybox 지역(월드 y 범위 -4800 ~ 600, 지면 상단 y=520) 기준이다.

| 파일 | 크기 | parallax | anchor | 역할 |
| --- | --- | --- | --- | --- |
| `avatar_lake/sky.png` | 1600x720 | 0.02 / 0.02 | 0, -390 | 하늘과 구름. 전체 불투명 |
| `avatar_lake/distant.png` | 1600x960 | 0.08 / 0.06 | 0, -570 | 먼 테푸이. 위쪽 투명 |
| `avatar_lake/middle.png` | 1600x1260 | 0.18 / 0.12 | 0, -840 | 중거리 테푸이, 폭포, 호수와 반사. 위쪽 투명 |

세 장 모두 가로로 반복한다.

호수 수면선은 `middle.png` 의 1005행이다. 스폰 지점에서 월드 y 495 에 오며, 지면 상단 y=520 보다 25 만큼 위다. 시작하자마자 호숫가에 선 구도가 되도록 맞춘 값이다.

## 현재 상태와 알려진 문제

2026-09-12 에 `sky.png` 를 실제 아트로 교체했다. 크기, 세로 커버리지, 알파, 균일 배율은 모두 계약을 만족한다. 리샘플 흔적도 없다.

다만 가로 반복 이음새가 맞지 않는다. 720 행 중 671 행에서 첫 열과 마지막 열이 다르고 채널 차이는 최대 90 이다. 스폰 지점에서 레이어 원점이 월드 x 392 에 오므로 이음선이 화면 안쪽을 지나간다.

이 때문에 `background_tests` 의 `tile edge continuity` 가 실패한다. 알고 남겨 둔 상태이며 하늘 이미지의 좌우 끝을 맞추면 해소된다. `repeatX` 를 끄는 것은 해법이 아니다. 폭 1600 으로는 가로 9600 인 지역의 왼쪽 끝을 덮지 못해 단색이 드러난다.

`distant.png` 와 `middle.png` 는 아직 생성기가 만든 검증용 이미지다.

## 새 이미지를 만들 때

### 크기를 바꾸는 표본화를 하지 않는다

이미지는 최종 크기로 직접 그린다. 다른 크기로 그린 뒤 늘리거나 줄이지 않는다.

참조 이미지에서 가져와야 한다면 1:1 픽셀 복사나 정수 배율 확대만 쓴다. 가로와 세로에 서로 다른 배율을 적용하는 일은 어떤 경우에도 하지 않는다.

첫 시도가 여기서 실패했다. 콘셉트 아트를 가로 0.5배, 세로 2.14배로 표본화해 하늘을 만들었고 이방성 4.3배 때문에 구름이 세로로 늘어나 보였다. 픽셀 데이터로도 드러난다. 세로로만 늘린 이미지는 중복 행 비율이 높고 중복 열 비율이 낮다.

### 알파는 0 또는 255 만 쓴다

중간 알파를 쓰지 않는다. 안티에일리어싱이 켜진 붓이나 부드러운 지우개, 그림자 레이어의 불투명도 조절이 중간값을 만든다. 저장 전에 확인한다.

가장 뒤 레이어는 전체가 불투명해야 한다. 뒤에 아무것도 없다.

### 가로 이음새를 맞춘다

가로로 반복하므로 마지막 열이 첫 열과 같아야 한다. 폭포나 구름이 경계에 걸리면 이음새가 보인다.

### 세로 높이와 anchor 는 도출한다

눈으로 맞추지 않는다. `py` 는 세로 시차, `H` 는 이미지 높이, `Vh` 는 보이는 세로 범위, `cMin`/`cMax` 는 카메라 중심의 세로 범위다.

```
H >= Vh + (cMax - cMin) * py
top(cMax) + H >= cMax + Vh/2                     모든 레이어
top(cMin) <= cMin - Vh/2                         뒤가 비치면 안 되는 불투명 레이어만
```

Greybox 의 카메라 범위는 4:3 에서 `cy ∈ [-4500, 300]`, 16:9 에서 `cy ∈ [-4575, 375]` 다. 양쪽을 모두 만족해야 한다.

전경 레이어를 `py = 0.20` 으로 추가한다면 4:3 이 `H >= 600 + 4800*0.20 = 1560` 을 요구하므로 1600 이상으로 잡는다. `H = 1600` 이면 아래쪽 조건에서 `anchor.y >= 360 - 1600 = -1240` 이 나온다.

하늘 레이어는 위아래 조건이 동시에 걸려 여유가 적다. 현재 값은 4:3 최상단에서 정확히 경계에 맞아 있다. 하늘의 시차나 높이를 바꾸면 반드시 두 조건을 다시 계산한다.

### 색과 대기원근

뒤 레이어일수록 밝고 채도가 낮다. 하늘이 가장 밝다. 이 순서가 깨지면 거리감이 뒤집혀 보인다.

호수 반사는 실시간 렌더링이 아니라 이미지에 미리 그려 넣는다.

## 검사

`tests/BackgroundTests.cpp` 가 다음을 검사한다. 이미지를 교체하면 이 검사를 다시 돌린다.

- 모든 픽셀의 알파가 0 또는 255 이고, 가장 뒤 레이어는 전부 불투명하다
- 위 세 부등식을 만족한다
- 마지막 열이 첫 열과 같다
- 렌더 정점의 텍스처 좌표 차이가 위치 차이와 가로 세로 모두 같다. 즉 배율이 1 이고 균일하다
- 4:3 과 16:9 양쪽에서 카메라를 위아래로 훑어도 단색 배경이 드러나지 않는다

```
ctest --test-dir build -C Release -R background_tests
```

## 검증용 임시 이미지 생성

현재 이미지는 `tools/generate_background.cpp` 가 목적지 픽셀을 직접 그려 만든 것이다. 소스 이미지를 읽지 않으므로 표본화가 일어날 여지가 없다.

빌드에 자동으로 포함되지 않고, 실행할 때만 PNG 를 덮어쓴다.

```
cmake --build build --config Release --target bg_generator
.\build\Release\bg_generator.exe .
```

실제 아트로 교체한 뒤에는 이 생성기를 실행하지 않는다.
